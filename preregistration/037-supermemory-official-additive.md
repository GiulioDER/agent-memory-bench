# 037: Supermemory additive official submission

Status: FROZEN before measurement.

## Question

Does the pinned Supermemory Claude Code integration improve execution graded task success over the
same `bare` control on the frozen AMB official grid, while remaining within the five hour wall time
limit?

## Submission design

This is an additive submission to the frozen `official-003` leaderboard base. It does not replace or
rerun the base arms. The measured roster is exactly `bare,supermemory`; no Recall arm is included.
The result will be joined to `official-003` by `(task_id, seed, condition)` and will be generated by
`scripts/build_arm_submission.py` from the published Supermemory records.

The run id is `supermemory-001`. It uses the current AMB master code plus the adapter in
`adapters/supermemory/`, the official plugin pinned in `config.frozen.json`, Supermemory Local, and
the amended deterministic static memory ingestion mode recorded in the adapter review files.
The model is `deepseek/deepseek-v4-flash`, the instruction variant is `protocol`, the corpus
condition assembly seed is 1, and the session seed count is 5. All five conditions are run:
`absent`, `superseded`, `contradictory`, `adjacent`, and `present`.

The current selection resolves to 73 task condition cells per session seed, 365 cells per arm, and
730 sessions across the two arms. The run uses the repository launcher on VPS2 with bounded block
concurrency 2. Prices are fixed at 0.0574 USD per million input tokens and 0.1148 USD per million
output tokens, as of 2026-08-22.

## Prediction and gates

I predict that the Supermemory arm will ingest the complete frozen condition feed, pass its
SessionStart and UserPromptSubmit lifecycle admission checks, and produce a positive or null delta
against `bare`. I predict that every condition will produce ordinary records, streams, costs and
admission artifacts, and that the complete run will finish in less than 18,000 seconds.

The result is eligible for additive leaderboard construction only if the adapter review record,
preregistration, full artifacts, per condition verification, base join, search rate floor, and
timing limit all pass. A timeout is an outcome, not a wiring failure, and is not retried.

## Frozen treatment

Supermemory uses the vendor plugin at commit
`e6227edc4f33b83317cfde2e7cd9790c794d22d1`, Supermemory Local version 0.0.8, the frozen config and
the official lifecycle hooks. The treatment is installed in an isolated Claude configuration for
each session. The control arm has no memory layer. The temporary local service is stopped and its
original environment is restored after collection.
