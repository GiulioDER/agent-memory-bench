## Question

Does the pinned Supermemory Claude Code integration improve execution graded task success over
the same `bare` control on the frozen AMB official grid?

## Submission identity

This is an additive official arm submission with run id `supermemory-003`. It preserves the
previous `supermemory-001` and `supermemory-002` artifacts unchanged. The measured roster is
exactly `bare,supermemory`; no Recall arm is included. The result is joined to the frozen
`official-003` leaderboard base by `(task_id, seed, condition)` and generated by
`scripts/build_arm_submission.py`.

The model is `deepseek/deepseek-v4-flash`, the instruction variant is `protocol`, the corpus
condition assembly seed is 1, and the session seed count is 5. All five conditions are run:
`absent`, `superseded`, `contradictory`, `adjacent`, and `present`.

The current selection resolves to 73 task condition cells per session seed, 365 cells per arm,
and 730 sessions across the two arms. The run uses the repository launcher on VPS2 with bounded
block concurrency 2. Prices are fixed at 0.0574 USD per million input tokens and 0.1148 USD per
million output tokens, as of 2026-08-22.

## Supermemory treatment

Supermemory Local remains pinned at version 0.0.8, and the official plugin remains pinned at
commit `e6227edc4f33b83317cfde2e7cd9790c794d22d1`. The adapter uses the vendor supported
`maxProfileItems` setting with `SUPERMEMORY_BENCHMARK_MAX_PROFILE_ITEMS=0`. Prompt-time lifecycle
recall remains enabled and is recorded by the required hooks.

The adapter ingests the complete rendered condition feed as explicit static memories through the
vendor supported `POST /v4/memories` write path. It preserves rendered transcript contents and
metadata, splitting only above 9,000 characters, and verifies both search and profile readiness
before any model session starts.

## Eligibility and reporting

The run is eligible for additive leaderboard construction only if every condition produces its
ordinary records, streams, costs and admission artifacts, the Supermemory lifecycle hooks pass
admission, the base join is reproducible, and `scripts/verify_run.py` plus
`scripts/build_arm_submission.py --check` pass. Wall time and ingestion time are reported as
measured values rather than used to discard an otherwise complete official result.
