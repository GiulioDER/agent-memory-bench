# Automatic official-run analysis

`analyze_official.py` turns the raw condition directories and the published summary into a
reproducible report and audit. It is the evidence layer behind the public leaderboard analysis
panel. The summary-only directory under `results/<run_id>/` remains unchanged.

## Generate and verify

```powershell
python -m scripts.analyze_official --run-id official-003
python -m scripts.analyze_official --run-id official-003 --check
python scripts/build_leaderboard.py --check
```

For a future frozen official run, replace `official-003` with its run id. For an accepted additive
vendor submission, add its reviewed run under `arm_runs` in the leaderboard config and rerun the
same command. The report then includes the joined vendor result, its submitted cost and token
rates, condition deltas, and its join scope. Wall time and per-cell spend remain unavailable for
an additive row unless the submission schema records those measurements.

The first command writes four artifacts under `reports/`:

* `<run_id>-analysis.json`, the machine-readable analysis consumed by the site;
* `<run_id>-analysis.md`, the human-readable comparison report;
* `<run_id>-audit.json`, the machine-readable integrity audit;
* `<run_id>-audit.md`, the human-readable audit summary.

The leaderboard config points to the JSON report through `analysis_report`. The leaderboard
builder verifies that the report was generated by the analyzer, belongs to the configured run,
and contains the current SHA-256 of `leaderboard_summary.json` before embedding it into
`site/data/leaderboard.js`.

## What the report covers

The report recomputes arm and condition scores from admitted raw records, then joins those
scores with the cost ledger. It includes:

* success rate, confidence interval copied from the published summary, solved and admitted cells;
* per-condition deltas against the designated `claude_md` baseline;
* total spend, tokens, spend per admitted cell, token efficiency, and pricing metadata;
* mean session wall time plus ingest time and ingest volume where recorded;
* strongest task-level gains and largest task-level losses;
* product, control, reference-track, and vendor-hold states.

Held products remain visible as held, but their withheld metrics are not used to declare a public
winner. This keeps an unresolved vendor review from becoming a silent comparison.

## Audit policy

The audit distinguishes data failures from methodological qualifications. A `fail` blocks a
clean official analysis. A `warn` preserves the report while requiring reader-facing disclosure.
The current official run warns about mid-run preregistration, an unmeasured write path, one
session per cell, and published token-rate denominators that do not match the raw cost ledger's
observed-session denominator. None of these warnings is silently normalized away.
